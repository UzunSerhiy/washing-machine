# №31Г — согласованность диагностических API

Четыре регрессионных теста для `GET /api/machine/readiness` и `GET /api/machine/motion-fault` (вызов обработчиков с имитацией аппаратуры):

1. Оба API согласованно отражают программную аварийную блокировку.
2. Нулевые ошибки и остановленные частотники не отменяют глобальную блокировку.
3. Таймаут RS485 отображается как недоступная телеметрия и `ready=false`.
4. Остановленный монитор не скрывает зафиксированную аварию.

Рабочий код не изменён. Проверка frontend, HTTP-клиента и аппаратных цепей в этот патч **не входит**. `ready` — диагностический показатель, а не разрешение на движение.

```bash
docker compose exec backend python -m pytest -q tests/test_step31g_api_state_consistency.py
docker compose exec backend python -m pytest -q
```

Ожидается 4 новых теста и 922 теста всего.
