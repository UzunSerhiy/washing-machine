# Шаг 28Б.1 — блокировка при каждом старте REAL backend

Проблема: при отказе записи аварии на диск там мог остаться старый `acknowledged: true`.

Решение: при каждом запуске REAL backend, до обслуживания HTTP-запросов, создаётся и синхронно сохраняется программная блокировка. Даже если прошлое состояние `acknowledged: true`, после рестарта требуется новая проверка трёх GAIN и явное подтверждение фактической остановки оператором. При невозможности записать состояние запуск приложения прерывается; нельзя продолжать работу с неисправным хранилищем.

Это намеренное изменение: **после каждого рестарта REAL backend потребуется операторское подтверждение**, даже если аварий не было. Это не отправляет RUN/RESET. Для снятия блокировки использовать только штатную процедуру после проверки физической безопасности.

Проверки: `docker compose exec backend python -m pytest -q tests/test_motion_fault_startup_interlock.py tests/test_motion_fault_persistence.py`, затем весь набор тестов.

Важные ограничения: не является safety-rated функцией; несколько workers/экземпляров backend не поддерживаются; остаётся необходимость отдельного аудита всех путей RUN и гонок. Пока не проверены тесты на оборудовании и сохранность данных в Docker, не выполнять реальное движение.
