# 30Ж.4 — диагностика ошибок уведомления и проверки восстановления

- `MotionFaultRuntime.last_notification_error` сохраняет ошибку callback уведомления. Существующая политика **без автоматического повтора** сохранена: повторный вызов обработчика после частичного выполнения мог бы привести к нежелательным побочным эффектам.
- GET `/motion-fault` дополнен полем `last_notification_error` (строка или null).
- Ошибка сохраняется при неудачной попытке восстановления, очищается **только после успешного** `acknowledge_exclusive`.
- Добавлены 3 теста: сбой callback, отказ восстановления при активной AUTO, отказ из-за телеметрии STOP, успешная очистка диагностики. Ни один тест не отправляет команду RUN/STOP на оборудование.

Важно: этот шаг добавляет наблюдаемость и регрессионные проверки, но не гарантирует корректное уведомление всех сессий при исключении внутри callback. В `main.py` обработчики уже вызываются независимо друг от друга; сбой одного не прерывает остальные. Восстановление по-прежнему требует неактивных сессий и подтверждения STOP всех трёх приводов. Физический E-STOP/RESET не заменяется программным кодом.

Проверка:

```bash
docker compose exec backend python -m pytest -q tests/test_step30zh4_recovery_faults.py
docker compose exec backend python -m pytest -q
```

Ожидаем 897 тестов (894 + 3). Не коммитить до полного прохождения Docker-тестов.
